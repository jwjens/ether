## 8 · Stage 1 plan (recorded here so it is not only in chat)

**Read-only closing screen. No firing, no routing, no audio changes.**

A finding that makes it cheaper: `announcements` and `announcement_schedule` **still carry
`trigger_type` and `close_offset_min`**. They sync, they are in `PATCHABLE`, and the resolver ignores
them — `dueTimeFor()` is `hmsNormalize(row.trigger_time)`, absolute only. So offsets need a resolver
change, **not a schema migration**.

Proposed closing-time storage — `station_config_kv`, one JSON value, so the unanswered scope question
does not block:

```json
{ "default": "22:00", "byWeekday": { "5": "23:00" }, "byDate": { "2026-10-31": "23:30" } }
```

Resolution order: **date → weekday → default.** Fill only `default` and the rest stay dormant.

*(Note: per-weekday closing time is not the weekday scope v48 removed. That was per-weekday
announcement ENTRIES — scheduling complexity that was cut. A park closing later on Fridays is a
property of the park.)*

| # | piece |
|---|---|
| 1 | `ClosingScreen.tsx`, reachable from the hamburger — a room with no door does not exist |
| 2 | Now playing — reuse existing deck state |
| 3 | Closing time — read/write the KV value, editable in the moment |
| 4 | Tonight's queue — today's `announcement_schedule`, with an offset **preview** computed in the panel |
| 5 | Plain language per row, derived from each row's real duck setting |
| 6 | Sanity rails — flag only, never block |

**Deliberately NOT in stage 1:** changing `dueTimeFor` (the engine keeps firing absolute times), any
firing, any deck or ducking change, the STOP button (stage 2). The panel *previews* offsets while the
engine still uses absolute times, so it can be built and reviewed **with zero risk to what airs**.
