## 1 · What is ALREADY DONE (in tree, committed, unverified at runtime)

All in `src/App.tsx`, commit `dc2c932` (4.4.142 — that version number was premature; ignore it).

### 1.1 · The gate hole is closed — this was the double sign-in

The gate used to read:

```js
if (firstRunChecked && !accountSignedIn) return <OnboardingFlow forceAuth … />
```

While `firstRunChecked` was still false the gate was **skipped entirely and rendering fell THROUGH it**.
The flag then resolved true, the gate fired, and the user was thrown back to sign-in **a second time**.
That fall-through **is** the double sign-in — a conditional gate with a hole in it, not a race to tune.

Now:

```js
if (!firstRunChecked) return <hold/>            // no path past this line
if (!accountSignedIn) return <OnboardingFlow forceAuth … />
if (!currentUser)     return <UserLogin … />
```

A hold cannot bounce: there is no fall-through to bounce back from.

### 1.2 · No station adopted before auth

`activeStationIdRef` called `getActiveStationIdSync()` inside its `useRef` initialiser — at **first
render**, before sign-in and before the PIN. Now seeded to `0`; the existing `[stationId]` effect is the
**only** writer and emits `STATION ADOPTED … (post-auth)` on the first real adoption, so the launch map
proves ordering.

### 1.3 · One canonical BOOTSEQ line

`bootSeq("AUTH COMPLETE — account signed in + PIN accepted")`, emitted once from `UserLogin.onLogin`,
replacing two overlapping lines that made the post-auth boundary ambiguous.

## 4 · Things not to get wrong

- **The daemon is untouched.** Broadcast does not wait for login; the APP does. Four stations air through
  this — do not gate the daemon.
- **`audiod/engine.js` changes require a full close + reopen**, not just an install — the daemon does not
  reload on update. (No daemon change is expected for D1.)
- **The watchdog exception stands**: an auto-restart while a station was actively streaming live may come
  back on air without re-sign-in. That is the ONLY bypass.
- **Do not "fix" the bounce with a retry, a timeout, or a re-render guard.** The hole was structural and
  is closed; if a bounce still occurs, find the new structural cause.
