# PFL for every channel (2026-09-26)

**Jeff's report:** "internal mic patched to a source channel, meter moves, channel OFF (correct, nothing on
air), but PFL gives no sound."

## Cause (read-only trace)

- **PFL did nothing, and never had.**
  - The strip's PFL button toggled its own lamp and called `onPfl?.()`.
  - **`FaderSection` passed no `onPfl` to any strip.** None at 4.6.49 (`b72b8ef`) either.
  - **The engine had no cue/PFL bus.** Its buses are PGM, LOCAL, STREAM, MONITOR, ROOM and AUX.
- **Source channels are heard locally only through the AUX monitor.** That path is post-fader and post-cut, so
  OFF means silent there. It was also silent on this machine: `AUX monitor device not found: "Speakers/Headphones
  (Realtek(R) Audio)"`, a name this machine doesn't have. That's a synced value, fixed in `42eb472`.
- **The only PFL that ever worked** was the old `MicChannel`'s browser cue path, removed with the browser mic
  (`f3e67cd`).

## Rulings

1. PFL goes to the station's main local output.
2. While any PFL is on, the programme there is **dimmed** by a station setting (default −12 dB, shown in
   Preferences → Audio). Air and stream are untouched.
3. Pre-fader, pre-cut, **post-rack**. A per-slot flag in `Params`; `AudioCmd::SetPfl`; `audio:set-pfl`;
   `FaderSection` wires every strip; the lamp shows the engine's echo.
4. `aux_monitor_device` becomes machine-local: its own commit, `42eb472`.

## Build

### Engine

- **`Params`:** `pfl: [bool; 12]` and `pfl_dim_db`.
- **Commands:** `AudioCmd::SetPfl { deck, on }` and `SetPflDim(db)`, clamped to −60…0 dB.
- **The default:** `PFL_DIM_DB_DEFAULT = −12` is the value the setting **shows** until it is changed.
- **In the callback:**
  - `pfl_any` is computed once per buffer;
  - the deck loop adds each PFL'd channel's pre-fader, pre-cut, post-rack signal to `cue_l/r`;
  - just before the device write, only when `pfl_any`: local = clamp(programme × dim + cue);
  - the MONITOR and LOCAL-loudness taps, PGM, the stream and the AUX send are all built before this;
  - no PFL means none of it runs.
- **The echo:** the meters frame carries `pfl` (a bitmask of the flags the callback **ran with**) and
  `pflDimDb`.

### Wiring

- **The daemon:**
  - `setPfl` and `setPflDim`;
  - it forwards `pfl` / `pflDimDb` on the meters event (contract RULE 6 now requires them);
  - a 3 s poll delivers the station's `pfl_dim_db` to its engine and to every fresh one.
- **main:** `audio:set-pfl` and `audio:set-pfl-dim`. **preload:** `setPfl` and `setPflDim`.

### UI

- **`FaderSection` passes `onPfl`** to the source channels, A/B/C and the lettered strips.
- **`ConsoleStrip`'s lamp** reads the engine's echo for an engine slot. A guest line keeps a local lamp: it isn't
  an engine channel.
- **Preferences → Audio → PFL:** the programme-dip setting (`PflSettings.tsx`, stored as `pfl_dim_db`).
- **Help:** `help-channel-faders.md` has a PFL section, including the ~40 ms note for a mic.

### Monitor level

The station's monitor faders scale the whole local output, programme and cue alike. PFL follows your
listening level.

## PFL output device (headphones) — build 2026-09-26

**Jeff's brief:**
- A PFL / cue output picker in Preferences → Audio: "same as main output" (default) or a named output device.
- Machine-local.
- With a cue device chosen, PFL goes ONLY to it, carrying the programme at the dim level for context; the main
  output is untouched.
- A missing device means "cue device not found" on the strip and in the Health Monitor, and silence. Never the
  speakers.
- Reuse the AUX monitor's device-open path.

### Engine

**One device-open path, two outputs.** The AUX monitor's output thread is generalised into `MonOut`: open by
the exact chosen name, **no fallback**, a 5 s retry while absent, a consumer-side resampler with a ±0.3 % drift
nudge, and underrun that decays to silence. It now serves the **AUX monitor** and the **PFL cue**.
- Both share the one `AuxCmd` queue into the callback, so it stays a single producer.
- The cue ring comes and goes through `AuxCmd::AttachCue` / `DetachCue`.
- The AUX behaviour is unchanged. The log labels are now "{AUX monitor|PFL cue} output opened / closed / device
  not found".
- Each output's cpal `Stream` is built and dropped on that thread (a `Stream` isn't `Send`).

**The cue status per station** (`CueStatus`): the chosen name, the state (same_as_main / opening / open /
not_found / failed), the rate, and the frames actually played (proof of flow). It is read by `audio_cue_state`,
and the meters frame carries `cueState`.

**`Params.pfl_to_device`** is set by `AudioCmd::SetCueDevice(name)`: true whenever a cue device is **chosen**,
whether or not it is present. In the callback:

| `pfl_to_device` | Cue ring | Callback behaviour |
|---|---|---|
| false | — | Main output = clamp(programme × dim + cue) while any PFL is on (unchanged). |
| true | Present (device open) | The cue ring gets clamp(programme × dim + cue) while any PFL is on, and silence otherwise (the stream keeps flowing, so its clock stays locked). **The main output is not touched.** |
| true | Absent (device missing) | **PFL is silent.** Nothing reaches the main output. |

### Wiring

- **LOCAL_ONLY:** `pfl_cue_device`.
- **The daemon:**
  - a 3 s poll delivers this machine's cue device to its engine, and to every fresh engine;
  - `setCueDevice` and `cueState`;
  - `cueState` is forwarded on the meters event (contract RULE 6 requires it).
- **main:** `audio:set-cue-device` (engine first, then `set-local`) and `audio:cue-state`. **preload:**
  `setCueDevice` and `cueState`.

### UI

- **Preferences → Audio → PFL → PFL output:** "Same as main output", or the engine's output devices ("(not
  connected)" when the saved one is missing), with the live state in words.
- **The strip:** while its PFL is on and the cue device is missing or failed, it shows **"⚠ cue device not found —
  PFL silent"**.
- **Health Monitor → PFL Output:** where PFL is going, the rate, and the seconds actually delivered.
- **Help:** `help-channel-faders.md` gains "PFL in headphones".
